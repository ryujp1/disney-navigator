## プロジェクトの背景・目的
テーマパークのような特殊な地理環境において、汎用マップアプリでは細かな歩行者用ネットワーク（裏道や広場など）が最適にルーティングされないという課題に着目しました。
本プロジェクトでは、OpenStreetMap（OSM）のオープンデータを活用し、「特定施設（ドメイン）に特化した高精度な歩行者ナビゲーション」の構築を技術的に検証しています。

## 現在の主な実装機能
- **パーク切り替え**: ランドとシーのマップデータを動的に切り替え。
- **高精度な経路探索**: OSMnxとNetworkXを利用し、施設の中心座標に最も近い「歩行可能なノード」を算出してDijkstra法で最短経路を計算。
- **ハイブリッドな出発地設定**: GPSを利用した「現在地」と、特定施設を指定した「シミュレーション」の両方に対応。各地点のピンには施設名を表示し、視認性を向上。
- **所要時間の提示**: 算出された距離（m）から、一般的な不動産基準（分速80m）に基づく徒歩所要時間を自動計算。
- **位置情報バリデーション**: パーク外での利用時に発生する強制マッピングバグを防ぐため、緯度経度による範囲制限を実装。

## 技術的なこだわり・工夫した点
- **非同期処理の制御**: ブラウザからの位置情報取得（JavaScript）とPython側の処理のタイミングのズレを解消するため、非同期処理の完了を待機する設計に変更し、安定した現在地取得を実現しました。
- **UXを考慮したエラー設計**: OSMデータが限定的なエリア（浦安市周辺）のみである特性を考慮し、エリア外でGPSを使用した際に「最も近い端のノード」へ強制マッピングされる挙動を制限。ジオフェンス（仮想境界線）を定義し、ユーザーに適切な案内（警告）を出すよう実装しました。

## 今後実装したい機能（アーキテクチャの進化とUX向上）
現状のStreamlit版プロトタイプから、本番運用を見据えて以下の機能拡張を構想しています。

1. **Google Maps API (Street View / AR) との連携**
   - 実際の風景（カメラ映像やストリートビュー）上にルートの線を描画する「AR歩行ナビゲーション」の実装。
2. **デバイスのジャイロ/コンパス連携（ヘディングアップ）**
   - ユーザーが向いている方角を取得し、アプリ内のマップの向きを進行方向に自動で合わせる機能。
3. **完全オフライン対応**
   - パーク内の通信混雑を考慮し、フロントエンドをReact等でPWA化。地図タイルと経路計算グラフ（JSON）をクライアント側にキャッシュし、電波ゼロでも動作する設計への移行。
4. **他テーマパークへの汎用化（スケーラビリティの確保）**
   - **現状**: 東京ディズニーリゾートのOSMデータ構造に最適化しているため、他の遊園地では施設タグの取得漏れやルート分断による位置取得エラーが発生する課題を確認済み。
   - **展望**: 施設ごとのタグ定義のブレを吸収する共通インターフェースを設計し、他の大規模テーマパークの座標を渡すだけでシームレスに展開・ルーティングできる汎用的なバックエンドアーキテクチャへの改修。
